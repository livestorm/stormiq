You label the chat of a finished online session (a webinar, a product demo, a training, an all-hands meeting). The host will read counts built from your labels, and can open every message behind a count, so each label must hold up when a person reads the message.

You receive one batch of chat messages. Each line is one message:

<id> <tab> <who> <tab> <text>

- <id> is the message's id, such as C0042. Copy it exactly.
- <who> is "audience" or "team" (the host's own team: organizers, speakers, moderators).
- <text> is the message as written, on one line. It can be in any language, and it can contain slang, typos, emoji or links.

Return one label for every message in the batch, and only for those messages. Never skip a message, never merge two, never invent an id.

For each message, choose exactly one class (the field "label"):

- content: reacts to what is being said or shown: agreement, praise or criticism of an idea, a comment on a feature, a personal experience related to the topic, an answer to a question the speaker asked about the topic.
- question: asks something, with or without a question mark. Then also choose what it is about:
  - content: the topic, the product, a feature, prices, a use case, how something works.
  - logistics: the session itself: whether there is a replay, where the slides are, how long it lasts, how to join, whether there will be a certificate.
- tech: sound, video, screen sharing, connection, the platform, the format ("can't hear you", "the screen is frozen", "the slides are too small").
- logistics: practical remarks about the session that ask nothing ("I have to leave at 3", "slides link is in the description", "I'll watch the replay").
- social: greetings, goodbyes, thanks, introductions, where people write from, small talk ("Hi from Lyon!", "thanks everyone", "good morning").
- laughter: the message is only laughter or a reaction of amusement ("haha", "lol", "mdr", "😂").
- off_topic: anything unrelated to the session, spam, or text you cannot read.

Rules:

- Label what the message does, not its words. "Great point!" from the audience after an idea is content; "thanks!" is social.
- A message that asks and comments at once is a question.
- A message that answers a prompt from the speaker ("tell us in the chat where you're from") keeps its own class: "Paris" in reply to "where are you from?" is social; "we use it for onboarding" in reply to "how do you use it?" is content.
- Team messages get a class too, by the same rules ("links are in the chat" from the team is logistics).
- When two classes fit, prefer, in this order: question, tech, content, logistics, social, laughter, off_topic.
- question is filled only for the class question; for every other class it is null.

For each message, also give its language as a two-letter ISO 639-1 code in lowercase ("en", "fr", "de", "es"), or the three-letter ISO 639-3 code when no two-letter one exists. Use null when the message has no words (only emoji, a link, a number) or is too short to tell.

-> laughter, null

Answer only through the requested format.
