# Frontend

A Vue 3 single-page app (Composition API, `<script setup>`) with vue-router, built by Vite into `frontend/dist`, which FastAPI serves. There is no Pinia, UI library or chart library: the store is a plain reactive module and charts are hand-built components. Architecture overview: [docs/architecture.md](../docs/architecture.md#frontend-code).

## Commands

From `frontend/`, or with `make web` and `make check` at the repo root:

- `npm run dev`: Vite on :5173, proxying `/api` to the API on :8000
- `npm test`: Vitest (`tests/`)
- `npm run lint`: ESLint
- `npm run build`: production build

## Store rules (`src/store/workspace.js`)

- **Session scope.** Every load, job start, poll and save captures the session it started for (`openSessionScope`: the id plus an `AbortController`). Opening another session or signing out aborts the old scope's requests, stops its pollers and drops late results. After every `await`, check `isCurrent(scope)` or call `assertCurrent(scope)` before writing state. AI jobs run against the session on screen (`displayedSessionScope()`), never against the Search form's inputs.
- **Loading flags** belong to the call that set them last (`beginLoading` returns a token for `endLoading`), so a stale flow's `finally` can't clear a newer flow's flag.
- **Polls survive blips.** Network errors, 408, 429, 5xx and an `unknown` job status are retried with backoff; 5 failures in a row, or any other error (401, 404…), stop the poll.
- **`state.workspace` is `markRaw`**, so Vue tracks the property rather than the thousands of rows inside it. Never mutate it in place; replace it: `setWorkspace({ ...state.workspace, outputs })`. Outputs-only job results are merged with `applyResult`.
- **401 anywhere** calls the handler `App.vue` registers with `onUnauthorized`: it clears the signed-in state and the workspace and shows a "reconnect" message. It doesn't navigate, so the sidebar's Connect button returns to the same page and shared links keep working. Account-level lists (session cards, events) drop responses that arrive after the account changed (`sameAccount`).

## API calls (`src/api.js`)

- Every request goes through `api.js`. Add session endpoints with its `sessionPath(id, suffix)` helper, which encodes the id; never interpolate ids into URLs by hand.
- Pass the scope's `{ signal }`, so switching session cancels the request.
- AI job polls use `getAiJobStatus`, which asks the server for outputs only.

## Views and components

- Routes are in `src/router.js`. Every view except the session list is lazy-loaded; keep it that way so the first page stays small.
- `/sessions/:sessionId/...` is a sharing contract. Don't break existing paths; add a redirect when one moves. Links from before the rename (`/single-analysis/...`) redirect to the same path under `/sessions` (`src/sessions/paths.js`, tested by `tests/session-paths.test.js`); keep those redirects.
- CSV downloads go through `src/utils/csv.js` (`buildCsv`, `escapeCsvCell`). Text cells starting with `=`, `+`, `-`, `@`, tab or CR get a leading `'`, because chat and questions are written by attendees.
- Styling follows [docs/brand.md](../docs/brand.md): Livestorm's design language, StormIQ's own identity. The headers show the co-brand "StormIQ for Livestorm": the StormIQ wordmark (`StormIqMark` with `:mark="false"`), then `components/ui/ForLivestorm.vue`, which shows the official Livestorm logo files from `src/assets/livestorm/` unchanged (on-light or on-dark, chosen by the `--siq-logo-on-*` tokens). Never use the Livestorm logo or icon as StormIQ's own logo or app icon, and never recolour or stretch it. The square spots (the favicons `public/favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, the collapsed sidebar, the compact top bar) show the "IQ" monogram (`components/ui/StormIqMark.vue`): the wordmark's own Sora 600 "I" and "Q", outlined. Never edit the favicons or the monogram's path by hand: `scripts/make_favicon.py` draws all of them from the font. The landing page's promo film is `public/media/stormiq-tour.mp4` (1080p H.264 at CRF 32, AAC 96k, `+faststart`, about 10 MB for two minutes) with its poster `stormiq-tour-poster.jpg`; a new film gets a new file name, so no cache keeps the old one; it loads only when played (`preload="none"`) and never autoplays.

## Design system (the v1 redesign)

There is one design, for everyone (the owner's decision, November 2026): no switch, no classic layout, no way back to the old StormIQ. Never add one.

- **The shell.** `App.vue` renders the top bar (`components/ui/TopBar.vue`) and the footer around every page. `index.html` sets `<html data-ui="v1">` statically, which the tokens' CSS keys on. Every page is a v1 page and fills the space between the top bar and the footer; there is no classic frame or classic stylesheet any more. The only global CSS is `src/design/tokens.css`: tokens, the font, and the page basics (box-sizing, `body` margin, link and control resets, `#app`'s height for the shell, a default focus ring, monospace `code`). Everything else is a component's own scoped style.
- **Signed out.** The shell renders `views/LandingView.vue` instead of the route when `design/landing.js`'s `showsLanding` is true (bootstrap answered, nobody signed in, not a public page), and gives the top bar no navigation items. A new page that anyone may open goes in `PUBLIC_PATHS`; anything else stays behind the landing page. The landing page reads no account or session data, and its example report is made-up and labelled as such.
- **Where it lives.** Tokens, the Sora `@font-face` and v1 page basics: `src/design/tokens.css`. Theme: `src/design/theme.js` (pure) and `useTheme.js` (Vue). Base components: `src/components/ui/` (`Card`, `CardHeader`, `IconTile`, `StatCard`, `Collapsible`, `StatusWord`, `Chip`, `UiButton`, `TipBar`, `Icon`, `StormIqMark`, `ForLivestorm`, `ThemeToggle`, `TopBar`, `ProgressSteps`: the one loader for every job a user waits on, its steps from a job's stage through `src/report/progress.js`, tested in `tests/progress.test.js`). Sora is in `public/fonts/` with its licence. Every component is shown at `/design`.
- **Rule for new UI: tokens only.** Colours, type sizes, radii, spacing and motion come from `--siq-*` custom properties; no raw hex, rgb or named colours in components (the token file is the one place for values). Shared v1 classes (components, `tokens.css`) start with `siq-`; a view's own scoped classes can use a short prefix of their own (the gallery uses `g-`). Don't add global element styles beyond the page basics in `tokens.css`: a form control sets its own colours, border, height and `select` chevron (`appearance: none` plus an icon). A scrolling wrapper that holds `.siq-sr-only` text (absolute) is `position: relative`, or that text widens the page on a phone.
- **Theme.** Light and dark come from the same tokens. The page follows the system until the user clicks the toggle; the choice is saved in `localStorage` (`stormiq:theme`). `index.html` applies the saved theme before first paint (keep it in sync with `theme.js`; `tests/design.test.js` runs the inline script and checks it agrees). Print stays light. `tests/brand.test.js` checks the logo swap and the logo files.
- **Less reading.** Prefer cards with an icon-tile header, stat cards and icon bullets to paragraphs; put anything longer than two lines in a `Collapsible`. Status is always icon + word (`StatusWord`), never colour alone.
- **The v1 Report** is `views/SessionReportView.vue` at `/sessions/:sessionId/report` (`/sessions/:sessionId` opens it). Its data comes from `src/report/useSessionReport.js` (`createSessionReport`), one per view: it follows the store's scope rules (an `AbortController` per open session, late results dropped, polls that survive blips and stop after 5 failures) and starts the session analysis only when the user clicks. The view names the session by `meta.session.title`. `App.vue` never loads the classic workspace; only the Follow-up page does, itself. Report charts live in `components/report/` (names of two words or more, for ESLint) and take their geometry from `src/report/chartGeometry.js` (clock labels, axis ticks, the ridge's path); the cover chart's marks and facts come from `src/report/cover.js`, over the chapters the server placed (`placed`, never `r + offset` in the page), tested in `tests/report-cover.test.js`; its replay (the card for each minute, from `GET /record/transcript` read by `createTranscriptLines`, and the key moments' pins) comes from `src/report/coverStory.js`, tested in `tests/report-cover-story.test.js`, and the chart is a keyboard slider whose value is the card in one line. "What stood out" renders `GET /record/findings` (`src/report/findings.js` words each finding from the server's values; a detector's thresholds live in `record/findings.py`, never in the page), tested in `tests/report-findings.test.js` against `tests/fixtures/findings-v1.json`. "The questions" lists Follow-up's desk read-only (`createQuestionDesk`, worded by `src/report/questions.js` with the desk's own words), the key moments under the Pulse render `GET /record/moments` (`createMoments`, `KeyMoments.vue`, worded by `src/report/moments.js`, tested in `tests/report-moments.test.js` against `moments-v1.json`; the Pulse's pins come from the same moments through `pulseMarks`'s third argument), and "Who spoke up" renders `GET /record/voices` (`createVoices`, worded by `src/report/voices.js`), tested in `tests/report-room.test.js` and `tests/report-voices.test.js` against `questions-v1.json` and `voices-v1.json`; both are read again when the session is fetched again or an analysis ends. "In short" picks its points from the findings, the moments and the desk (`src/report/summary.js`, tested in `tests/report-summary.test.js`); the checks that couldn't run and the audience parts with nothing to show are listed in "Method and data quality", not in their sections. French templates live in `src/report/findingsFr.js` (every English template has its French twin), and the "Next time" library in `src/report/nextTime.js` (as many lines in French as in English, event craft only). New Report sections are components fed by the record, built against the fixtures below. "Fetch the chat again" is shared by the session's pages (`src/report/sessionRefresh.js` `refetchSession`): it runs outside any page's scope, so leaving a tab never cancels it, bumps `refreshes[id].version` for the open pages to reload, and drops the workspace store's copy (`forgetSession`).
- **Numbers come from the server.** The v1 Report renders `record.measures[id]` from `GET /api/sessions/{id}/record` and computes no formula: no ratio, median, sum or threshold of its own. A percentage is `value` formatted; the "How we know" drawer shows `num`, `den`, `excluded`, `coverage` and `livestorm` as sent; a hidden value (`insufficient`, `unresolved`, `unavailable`) stays hidden, and an `unresolved` measure has no `num` or `den`. "Excludes your team (n)" is `excluded.total`; a time in minutes comes from the measure's own seconds (`coverage.medianAttendanceS`, a row's `medianAttendanceS`), never from a share times a length. A grouped measure's table or map renders its `rows` in order, by `key`: a null row value stays an empty cell, a row's own `state` says why (an empty `wrote` or `wroteRate` on a channel or segment row: the measure's `coverage.chatAuthors` or `coverage.questionAuthors` is `unresolved`), and an `(other)` or `direct_or_unknown` row is a label, never a channel or an answer to compare. Empty `rows` (no source at all, no select field) means no table; `coverage` says why. Formulas and states: [docs/product.md §13](../docs/product.md#measures-v1-report).
- **The clock gate comes from the server.** Whether the transcript may be read against the chat is decided once, server-side: show a claim measured in seconds only when `meta.clock.alignment.allows.seconds` is true, one in minutes only when `allows.minutes` is, and the Pulse's speech lanes only when `record.pulse.speech.shown` is. Never decide from `status`; it only labels the clock badge ([docs/product.md §13](../docs/product.md#alignment-probe-v1-report)).
- **Icons** are Lucide paths vendored in `Icon.vue` (licence in `components/ui/LICENSE-lucide.txt`); Livestorm's icon font is proprietary and can't be in this public repo. Add an icon by copying its SVG children from Lucide into `ICONS`.
- **Accessibility.** 40px targets (`--siq-target`), focus rings from `.siq-fx:focus-visible` (drawn inside, `outline-offset: -3px`, wherever a parent clips: a scrolling tab row, a flush card), transitions on named properties only (never `transition: all`), and `prefers-reduced-motion` honoured. Edges and current-item marks drawn with `box-shadow` also need a `@media (forced-colors: active)` border, because High Contrast removes shadows. A link that must not navigate while disabled uses `RouterLink`'s `custom` slot (a plain `@click` on `RouterLink` runs after it navigates).

## Tests

Vitest, with fake timers for polls. `tests/workspace.test.js` mocks `api.js` and covers the store's async behaviour (scopes, aborts, polls, loading flags); `tests/api-and-csv.test.js` covers URL building, 401 handling and CSV escaping. `tests/report.test.js` covers the v1 Report's data layer (loading, following or starting an analysis run, backoff, late answers, closing) and its wording; `tests/report-charts.test.js` its chart geometry; `tests/report-vitals.test.js`, `tests/report-audience.test.js`, `tests/report-room.test.js` and `tests/report-method.test.js` the wording of the vitals, of the audience section, of the room and questions sections, and of "Method and data quality". Why a number is hidden comes from the measure (`state`, `coverage.missing`, `gate`): never write a threshold into the page. The Report prints: `SessionReportView` opens every closed `<details>` on `beforeprint` and closes them on `afterprint`, and its `@media print` block hides screen-only controls; a new section's buttons are hidden there through `.siq-btn`, and anything else interactive needs its own print rule. The chat's text, for a count that opens its messages, comes from `GET /record/chat` through `createSessionReport().loadChat()`, once per open session (`state.chat.byId`); render it as text, never as HTML. `tests/transcript-lines.test.js` and `tests/transcript.test.js` cover the Transcript tab: its lines (`src/transcript/lines.js`: one clock only when the server sent `clock.interleave`, never `r + offset` worked out in the page; filters, the room's authors and the author filter, the chat column's own search, each speaker's colour; unclear words; the subtitles) and its data (`src/transcript/useTranscript.js`: the job followed, a transcript started only on a click, names saved, late answers dropped), against `tests/fixtures/transcript-v1.json`, which the backend generates from the real route; `tests/transcript-stats.test.js` covers the wording of "Speaking stats" (`src/transcript/stats.js`). The session's navigation bar is one component, `components/report/SessionTabs.vue` ("Sessions" and the title, then the three pages), the first child of each session page so it never moves between them; it replaces their breadcrumbs. `tests/followup.test.js` covers the Follow-up tab's outputs (`src/followup/outputs.js`, the attendee follow-up in its own group, For the audience, Surprise me in its corner, shown only while `state.org.surpriseEnabled` is true: the server's word from `/api/bootstrap`, false until it answers, tested in `tests/workspace.test.js`, the Deep analysis read-only under "Earlier outputs" and each output's earlier versions: `versionsQuery`, `versionText`, `earlierVersions`), `tests/output-versions.test.js` their data (`src/followup/useOutputVersions.js`: one load per output with its own signal, late answers dropped) and its Markdown (`src/followup/markdown.js`: blocks of text, never markup). `tests/questions.test.js` covers the question desk: its words (`src/followup/desk.js`: filters by status and by source (`SOURCES`, `sourceOf`, `sourceCounts`: the Q&A tab in `--siq-s2`, the chat in `--siq-s1`, always with their word and icon), summary, status words, located passages and what the host can do with them; the status comes from the server, never worked out in the page) and its data (`src/followup/useQuestionDesk.js`: loaded and saved with the scope's signal, late answers and late saves dropped, a failed save keeping the desk), against `tests/fixtures/questions-v1.json`, which the backend generates from the real route. `tests/chapters.test.js` covers Follow-up's "Chapters and show notes" (`src/followup/chapters.js`, `useChapters.js`) against `tests/fixtures/chapters-v1.json`, generated the same way; `tests/transcript-lines.test.js` also covers the Transcript's chapter headings. The desk needs no transcript and calls no model. The Follow-up page is the one v1 page that uses the classic workspace: it calls `loadSessionById` itself (App.vue never does) and makes outputs only through the store's AI flows, on a click. AI text is rendered with `components/report/MarkdownBlocks.vue`, never `v-html`. `tests/gif.test.js` covers which chat links show as GIFs (`src/utils/gif.js`: GIPHY's and Tenor's media files over https, shown under the message's other words; anything else stays text). `tests/figures.test.js` covers Before you share (`src/followup/figures.js`, `useFigureChecks.js`) against `tests/fixtures/figures-v1.json`, which the backend generates from the real route. `tests/landing.test.js` covers when the signed-out landing page shows, `tests/sessions-list.test.js` the v1 Sessions page's rows, filters, sorts and counts (`src/sessions/list.js`), `tests/library.test.js` its library cells (`src/sessions/library.js`: the shape, the numbers as the Report shows them, the lead finding with the Report's templates) and their loading (`src/sessions/useLibraryRows.js`: only the rows on screen, a few at a time, each once, everything dropped on close), and `tests/add-session.test.js` the Add session page's events, sessions and pasted IDs (`src/sessions/add.js`). `tests/design.test.js` covers the theme (defaults, persistence, storage that throws, the system preference), `safeStorage`, the `index.html` pre-paint script against `theme.js` and its static `data-ui`, and `useTheme`. Add or update a test with every store change.

`tests/fixtures/record-v1.json` is what `GET /api/sessions/{id}/record` returns for a synthetic session ([docs/api.md](../docs/api.md#the-v1-record)), and `record-v1-crowd.json` what it returns for a larger one, whose grouped measures (concentration, room map, channels, segments, lead time) show their rows. The backend generates both from the real route, and a backend test fails when either drifts; build v1 Report components against them and never edit them by hand.
